# Internal CRM API

REST API для учёта звонков и назначения встреч менеджерам. Интерфейс, авторизация и роли не входят в задание.

## Требования

- Docker Desktop с Docker Compose v2.
- Для локальных `ruff` и `pytest`: Python 3.12 или новее и виртуальное окружение.

## Запуск API с нуля

Из корня репозитория запустите:

```powershell
docker compose up --build -d
```

Compose поднимет PostgreSQL 16 и API. При старте контейнер API применяет Alembic-миграцию, затем запускает Uvicorn на порту `8000`.

Проверить состояние контейнеров и API:

```powershell
docker compose ps
Invoke-RestMethod http://localhost:8000/health
```

Health check должен вернуть `status: ok`. Интерактивная документация OpenAPI доступна по адресу <http://localhost:8000/docs>.

Остановить контейнеры, сохранив данные PostgreSQL:

```powershell
docker compose down
```

## Тесты и Ruff

Зависимости можно установить в локальное виртуальное окружение:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Тесты используют отдельную PostgreSQL-базу `crm_test_db` на порту `5433`. Поднимите её и задайте URL перед запуском:

```powershell
docker compose up -d test-db
$env:TEST_DATABASE_URL = "postgresql+psycopg://crm_user:crm_password@localhost:5433/crm_test_db"
ruff check app tests
pytest -v
```

Тестовая фикстура проверяет, что имя базы содержит `test`, создаёт схему и очищает таблицы только в этой базе. Основная база `crm_db` для тестов не используется. После выполнения тестов фикстура удаляет тестовые таблицы.

## Эндпоинты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/companies` | Создать организацию |
| `GET` | `/companies?status=&limit=&offset=` | Список организаций с фильтром и пагинацией |
| `POST` | `/calls` | Записать результат звонка, при необходимости связать или создать встречу |
| `POST` | `/meetings` | Назначить встречу |
| `PATCH` | `/meetings/{meeting_id}` | Перенести или отменить встречу |
| `GET` | `/managers/{manager_id}/schedule?date=YYYY-MM-DD` | Расписание менеджера за календарный день Алматы |

Файл [`requests.http`](requests.http) содержит последовательные примеры запросов для REST Client в VS Code и JetBrains IDE.

## Реализованные правила и допущения

- БИН организации — строка из 12 цифр, уникальная в базе.
- Встреча длится ровно 60 минут и должна целиком проходить с понедельника по пятницу с 09:00 до 18:00 по `Asia/Almaty`. Поэтому начало в 17:00 допустимо, а в 17:01 — нет.
- Входные даты должны содержать часовой пояс; API нормализует их и отдаёт в UTC в ISO 8601.
- У менеджера не бывает пересекающихся активных встреч; стык встреч разрешён.
- Принята строгая трактовка правила организации: у неё может быть только одна активная (`scheduled`) встреча одновременно в базе, даже если новая встреча назначается на другую дату. После отмены можно назначить новую.
- Для защиты от гонок сервис блокирует строки менеджера и организации через `SELECT ... FOR UPDATE` в фиксированном порядке. PostgreSQL дополнительно защищает расписание менеджера ограничением `EXCLUDE USING gist`, а активную встречу компании — частичным уникальным индексом.
- `meeting_set` требует связать звонок с активной встречей этой же организации, ещё не привязанной к другому звонку, либо создать встречу атомарно в запросе звонка.
- При переносе `initial_start_time` сохраняет первоначальное время; при отмене освобождаются слот менеджера и активность встречи компании.
- Авторизация, роли, очереди, уведомления, кэш и фронтенд сознательно не добавлялись.

## Переменные окружения

Основная база внутри Compose настроена в `docker-compose.yml`. Для локального запуска можно задать `DATABASE_URL`, например:

```powershell
$env:DATABASE_URL = "postgresql+psycopg://crm_user:crm_password@localhost:5432/crm_db"
```

Для тестов используется отдельная переменная `TEST_DATABASE_URL`, см. команды выше и [`.env.example`](.env.example).
