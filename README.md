# Внутренняя CRM — REST API

API для учёта звонков и назначения встреч менеджерам. Ниже — пошаговый запуск и готовые запросы для ручной проверки через Swagger UI.

## 1. Что нужно установить

- Git, чтобы получить репозиторий.
- Docker Desktop с Docker Compose v2. Перед запуском Docker Desktop должен быть открыт и показывать, что Docker Engine работает.
- Для локального запуска тестов — Python 3.12 и выше.

Python и PostgreSQL для обычного запуска API отдельно устанавливать не нужно: они запускаются в Docker-контейнерах.

## 2. Получить проект и запустить API

Откройте PowerShell и выполните команды:

```powershell
git clone https://github.com/aidynbot/task-b.git
cd task-b
docker compose up --build -d
```

Первый запуск скачает образы и соберёт контейнер API; это может занять несколько минут. Дождитесь, пока PostgreSQL станет healthy и API запустится:

```powershell
docker compose ps
docker compose logs api
```

У контейнера `db` статус должен быть `healthy`, у `api` — `Up`. В логах API должны быть строки `Application startup complete` и `Uvicorn running on http://0.0.0.0:8000`. При старте API автоматически применяет миграции Alembic.

Проверьте API:

```powershell
Invoke-RestMethod http://localhost:8000/health
```

Ожидаемый ответ:

```json
{
  "status": "ok"
}
```

## 3. Открыть документацию и выполнить запрос

Откройте в браузере <http://localhost:8000/docs>. Для каждого запроса в Swagger UI:

1. Найдите нужный эндпоинт и нажмите на его строку, чтобы раскрыть описание.
2. Нажмите **Try it out**.
3. Вставьте JSON из примеров ниже в поле **Request body**. Для GET-запроса задайте параметры в полях формы.
4. Нажмите **Execute**.
5. Проверьте **Server response**: код и тело ответа показаны под формой.

Также можно запускать запросы по порядку из [`requests.http`](requests.http) в VS Code с расширением REST Client или в JetBrains IDE. Этот файл автоматически сохраняет ID из ответов.

## 4. Пройти успешный сценарий

### 4.1 Создать организацию — `POST /companies`

Раскройте `POST /companies`, нажмите **Try it out**, вставьте тело и нажмите **Execute**:

```json
{
  "name": "ТОО Пример",
  "bin": "123456789012",
  "phone": "+7 (700) 123-45-67"
}
```

Ожидаемый код: `201 Created`. Ответ содержит `id` компании. Запомните его и подставляйте вместо `1` в следующих примерах. БИН должен быть уникальным; если запускаете сценарий повторно, замените его на другие 12 цифр.

Телефон принимается в нескольких формах и в ответе приводится к `+7XXXXXXXXXX`:

```json
{ "name": "Пример с 7", "bin": "223456789012", "phone": "7 700 123-45-67" }
```

```json
{ "name": "Пример с 8", "bin": "323456789012", "phone": "8 (700) 123-45-67" }
```

### 4.2 Назначить встречу — `POST /meetings`

Подставьте ID созданной компании. `manager_id` можно выбрать из списка тестовых менеджеров ниже. Время в API передаётся в UTC: `04:00Z` соответствует `09:00` в Алматы.

```json
{
  "company_id": 1,
  "manager_id": 1,
  "start_time": "2026-11-23T04:00:00Z"
}
```

Ожидаемый код: `201 Created`. Ответ содержит ID встречи (`id`), который понадобится далее. Встреча длится ровно 60 минут.

### 4.3 Записать звонок и связать его со встречей — `POST /calls`

Подставьте ID той же компании и встречи. Для результата `meeting_set` передайте ровно одно из полей: `meeting_id` или вложенное `meeting`.

```json
{
  "company_id": 1,
  "manager_id": 1,
  "result": "meeting_set",
  "meeting_id": 1
}
```

Ожидаемый код: `201 Created`. Связанная встреча должна быть активной, принадлежать этой компании и ещё не быть привязанной к другому звонку.

### 4.4 Получить список организаций — `GET /companies`

Например, задайте `status=meeting_set`, `limit=20`, `offset=0`. Запрос:

```text
GET http://localhost:8000/companies?status=meeting_set&limit=20&offset=0
```

`offset` — сколько записей пропустить перед выдачей. Например, `limit=20&offset=20` вернёт следующую страницу.

### 4.5 Посмотреть расписание — `GET /managers/{id}/schedule`

В Swagger введите ID менеджера и дату календаря Алматы:

```text
GET http://localhost:8000/managers/1/schedule?date=2026-11-23
```

Ответ содержит `items` с активными встречами за указанный день. Время встреч в ответе — UTC.

### 4.6 Перенести встречу — `PATCH /meetings/{meeting_id}`

Введите ID встречи и передайте только новое время начала:

```json
{
  "start_time": "2026-11-23T05:00:00Z"
}
```

Ожидаемый код: `200 OK`. `initial_start_time` останется прежним, `end_time` пересчитается, а `rescheduled_count` увеличится.

### 4.7 Отменить встречу — `PATCH /meetings/{meeting_id}`

Для отмены уберите `start_time` и отправьте только статус:

```json
{
  "status": "cancelled"
}
```

Ожидаемый код: `200 OK`. После отмены активность встречи прекращается и организация может получить новую встречу.

## 5. Другие варианты `POST /calls`

Если менеджер не дозвонился, отправьте:

```json
{
  "company_id": 1,
  "manager_id": 1,
  "result": "no_answer"
}
```

Если организация отказалась:

```json
{
  "company_id": 1,
  "manager_id": 1,
  "result": "refused"
}
```

Можно создать встречу и звонок атомарно одним запросом. Если встреча не пройдёт проверку, звонок тоже не сохранится:

```json
{
  "company_id": 2,
  "manager_id": 2,
  "result": "meeting_set",
  "meeting": {
    "start_time": "2026-11-23T06:00:00Z"
  }
}
```

## 6. Проверить ошибки

### Пересечение встреч менеджера — `409 Conflict`

Сначала создайте активную встречу на `2026-11-23T04:00:00Z` для менеджера `1`. Затем создайте **другую** компанию и отправьте для неё встречу этому же менеджеру, например:

```json
{
  "company_id": 2,
  "manager_id": 1,
  "start_time": "2026-11-23T04:30:00Z"
}
```

Интервалы пересекутся, поэтому ожидается `409 Conflict` с сообщением о занятом менеджере. Стык интервалов, например `04:00Z` и `05:00Z`, разрешён.

### У организации уже есть активная встреча — `409 Conflict`

После назначения встречи для компании попробуйте назначить этой же компании ещё одну, даже на другое время и другому менеджеру:

```json
{
  "company_id": 1,
  "manager_id": 2,
  "start_time": "2026-11-23T07:00:00Z"
}
```

Пока первая встреча имеет статус `scheduled`, ожидается `409 Conflict`. Сначала отмените её запросом `PATCH /meetings/{meeting_id}`.

### За пределами рабочего времени — `422 Unprocessable Entity`

`17:30` по Алматы соответствует `12:30Z`. Часовая встреча не помещается до 18:00:

```json
{
  "company_id": 3,
  "manager_id": 3,
  "start_time": "2026-11-23T12:30:00Z"
}
```

Тот же код вернётся для выходного дня или даты без часового пояса, например `2026-11-23T04:00:00`.

## 8. Запустить автоматические проверки

Если локальное виртуальное окружение ещё не создано, выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\Activate.ps1
```

Поднимите отдельную тестовую PostgreSQL-базу. Она работает на порту `5433` и не использует данные основной `crm_db`:

```powershell
docker compose up -d test-db
```

В PowerShell задайте URL тестовой базы и запустите линтер и тесты:

```powershell
$env:TEST_DATABASE_URL = "postgresql+psycopg://crm_user:crm_password@localhost:5433/crm_test_db"
ruff check app tests
pytest -v
```

Если PowerShell не позволяет активировать окружение или его не активировали, вместо последних двух команд запускайте `\.venv\Scripts\ruff.exe check app tests` и `\.venv\Scripts\pytest.exe -v`. Тестовая фикстура проверяет, что имя БД содержит `test`, создаёт таблицы и менеджеров, очищает их между тестами и удаляет тестовые таблицы после завершения.

## 9. Остановить API

Чтобы остановить контейнеры и сохранить данные основной базы:

```powershell
docker compose down
```

## Допущения и границы

- БИН — уникальная строка из 12 цифр.
- Телефон Казахстана принимается с `+7`, без `+` с `7` или с внутренним префиксом `8`; сохраняется нормализованным как `+7XXXXXXXXXX`.
- Встреча длится 60 минут; рабочие часы — понедельник–пятница, 09:00–18:00 `Asia/Almaty`. Все значения datetime в API — aware ISO 8601 UTC.
- Активные встречи менеджера не пересекаются. У компании может быть только одна активная встреча, даже на разные даты; отменённая встреча не блокирует следующую.
- Создание и перенос защищены блокировками строк и ограничениями PostgreSQL.
- Авторизация, роли, очереди, уведомления, кэш и фронтенд не добавлялись.
